# RakamLah v0.1 Design

## Objective

RakamLah is an independent, open-source TolongLabs product for producing repeatable browser walkthrough videos. It
combines scripted Playwright capture, beat-aware narration, local text-to-speech, burned subtitles, background music,
and media verification without assuming a particular application framework or deployment provider.

Version 0.1.0 is a portable headless foundation. A richer interactive CLI/TUI customization experience belongs on the
public roadmap and must not be presented as already implemented.

## Product Boundary

RakamLah owns the recording pipeline, configuration contracts, reusable media processing, validation, documentation,
and a neutral example. A consuming project owns its URL, selectors, authentication, data fixtures, warm-up behavior,
browser choreography, narration, and product-specific assertions.

The repository must not reference or identify any project from which earlier internal experiments were learned. Its
public story, examples, issues, release notes, and Git history describe RakamLah only as a TolongLabs product.

## Release Scope

The first release ships:

- A public GitHub repository at `TolongLabs/RakamLah` with `main` as the default branch.
- A portable headless command surface for humans and agents.
- A configuration loader and project adapter contract.
- Browser capture, beat timing, local narration, subtitle generation, BGM mixing, and output verification utilities.
- A self-contained neutral fixture and example scenario that can run without an external service.
- The existing TolongLabs BGM suite and Chatterbox reference samples, byte-for-byte, tracked through Git LFS.
- A polished README banner and a `docs/README.md` landing page structured like TolongLabs' preferred repository docs.
- Concise agent instructions and compatible entrypoints for Codex, Claude, and Gemini, plus generic headless guidance
  for other agents.
- Community health, security, contribution, responsible-use, media-license, and release-history files.
- A public roadmap represented by GitHub issues and labels rather than unchecked README promises.
- A tagged `v0.1.0` public alpha release.

The first release does not ship:

- An interactive TUI.
- A full subtitle/audio/filter configuration studio.
- Chapter-aware partial recapture.
- Deterministic network cassette recording.
- A resident TTS daemon.
- Hosted rendering or a cloud service.

## Architecture

### Command Surface

`bin/rakam.mjs` exposes stable non-interactive commands:

- `rakam doctor` checks Node, Python, Playwright, ffmpeg, ffprobe, media, and configuration prerequisites.
- `rakam validate` loads and validates configuration and the scenario adapter without launching a browser.
- `rakam capture` records the configured browser scenario and writes video plus beat metadata.
- `rakam narrate` builds voice segments, schedules them against beats, burns subtitles, and mixes optional BGM.
- `rakam run` executes capture followed by narration and verification.
- `rakam verify` probes a completed deliverable and checks duration, dimensions, codecs, audio, and required beats.

Every command accepts `--config <path>` and `--json`. Human output goes to stderr when JSON mode is enabled; stdout
contains one final JSON object. Success exits 0, invalid input exits 2, missing dependencies exits 3, capture/render
failure exits 4, and verification failure exits 5. Commands never prompt when `--json` or `CI` is set.

### Configuration

Projects provide an ESM configuration file. The schema covers project name, output directory, browser viewport,
scenario module, narration source, video dimensions, subtitle defaults, TTS choice, voice reference, BGM, duration
bounds, and environment overrides. All paths resolve relative to the configuration file, making configurations
portable across working directories.

Configuration defaults remain conservative and observable. Environment variables may override secrets or
machine-local paths, but configuration examples contain no credentials.

### Adapter Contract

A project scenario exports `walk(context)` and may export `warmup(context)` and `audit(result)`. The context provides
the Playwright page, validated configuration, `mark(beat)`, and `hold(beat)` helpers. RakamLah records ordered beat
events and rejects missing, duplicated, or out-of-contract beats before accepting a capture.

The neutral example hosts a tiny local HTML fixture and demonstrates navigation, a form interaction, a result reveal,
smooth scrolling, proof assertions, narration, and final rendering.

### Media Pipeline

Narration text is resolved into one manifest consumed by both TTS and subtitle generation. Audio is content-addressed
by engine, voice/reference hash, speed, and text. Beat-aware scheduling prevents speech from crossing into the wrong
visual moment. FFmpeg normalizes capture, mixes narration and optionally ducked BGM, burns subtitles, and exports H.264
video with AAC audio.

Bundled MP3 files live under `media/bgm/` and `media/voices/`. `.gitattributes` tracks them through Git LFS. A media
manifest records filenames, SHA-256 checksums, duration, intended role, and the redistribution terms confirmed by
TolongLabs. Responsible-use guidance prohibits deceptive impersonation and requires consent for added voice samples.

### Agent Accessibility

`AGENTS.md` stays under 200 lines and points to focused documents. `CLAUDE.md` and `GEMINI.md` point compatible tools
to the same canonical instructions. `docs/agent-integration.md` gives any agent a deterministic sequence using the
headless JSON commands, including expected outputs and exit codes. No agent integration depends on a proprietary MCP
server or one vendor's prompt syntax.

Repository-local engineering skills may be vendored when they are product-neutral and licensed for redistribution.
Project-specific skills, agents, and documentation are excluded. Hook scripts must be retargeted and checked for
machine paths, credentials, or unrelated product names.

## Documentation and Brand

The landing README begins with the generated banner, a crisp value proposition, status table, the rule shaping the
repository, a start-here table, a concise architecture diagram, installation, a five-minute neutral example, command
reference, layout, agent usage, media terms, contribution flow, roadmap link, and release status. It must clearly label
v0.1.0 as an alpha and never imply roadmap features already exist.

The banner is a cinematic wide raster asset combining a browser frame, command-line cursor, recording timeline, audio
waveform, and luminous record/playhead motif. The exact word `RakamLah` is the only required in-image text. The palette
uses near-black, electric cyan, warm coral-red, and restrained off-white; the composition remains legible in GitHub's
light and dark themes.

## Quality and Safety

- New runtime behavior is developed test-first.
- The neutral example and all tests use synthetic data.
- No `.env`, token, absolute developer path, generated recording, model cache, or worker log enters Git history.
- A repository-wide scan must find no unrelated project names or stale URLs.
- Audio files must match their source SHA-256 checksums after copy and after LFS checkout.
- Headless JSON output is schema-stable and contains no decorative text.
- The README and roadmap distinguish implemented, experimental, and planned capabilities.
- The public repository is created only after local tests, artifact inspection, and secret/name scans pass.

## Publishing

The local repository is committed on `main`, then created publicly under the TolongLabs organization. Repository
description, topics, issue labels, and roadmap issues are configured through GitHub CLI/API. The `v0.1.0` tag and public
alpha release are created only from the verified pushed commit. Release notes summarize shipped capabilities,
limitations, system requirements, media packaging, and the issue-based roadmap.
